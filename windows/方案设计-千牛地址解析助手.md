# 千牛地址解析助手 — 方案设计文档

> 文档版本：v1.1  
> 更新日期：2026-07-01  
> 用途：供 Win 环境落地开发参考（Mac 侧已完成需求分析与方案设计）

---

## 1. 项目背景

客户使用千牛/快递批量发货，需将**非结构化收货文字**自动填入标准 Excel 导入模板（`5.15(3).新表格.xlsx`），并支持**自定义关键词整行标红**，便于人工复核高风险或特殊地址。

同时，产品需自然植入 **晴红AI 大模型中转站**，作为复杂样本解析能力与商业化入口。

---

## 2. 表格结构（已确认）

模板文件：`5.15(3).新表格.xlsx`

| 列 | 字段名 | 是否必填 | 说明 |
|----|--------|----------|------|
| A | 收件人 | 必填 | 可含平台后缀，如 `田伟[0201]` |
| B | 手机号 | 必填 | 11 位中国大陆手机号 |
| C | 收货地址 | 必填 | 可含后缀，如 `...125户[0201]` |
| D | 平台订单号 | 非必填 | 可选填 |
| E | 商品信息 | 非必填 | 可选填 |
| F | 规格信息 | 非必填 | 可选填 |
| G | 商品数量 | 非必填 | 可选填 |
| H | 重量 kg | 非必填 | 可选填 |
| I | 备注 | 非必填 | 可选填 |

**已有示例：**

```
行2: 曹 | 13076031512 | 广东省惠州市惠东县吉隆镇人民路285号鸿震远
行3: 田伟[0201] | 15781202007 | 安徽省亳州市蒙城县庄周街道京开城B区9栋125户[0201]
```

**重要业务规则：** `[0201]`、`[9196]` 等平台标识**不是垃圾字符**，需保留在姓名或地址字段中（是否同步写入 D 列「平台订单号」需与客户二次确认）。

## 3. 输入样本与解析难点

### 3.1 样本 1（姓名在前，紧凑无分隔）

```
蔺玉泉[9196]15781066479天津市天津市河东区富民路街道月牙河南路与娄山道交叉路口往北约100米金月湾花园7号楼603[9196]
```

期望输出：

| 收件人 | 手机号 | 收货地址 |
|--------|--------|----------|
| 蔺玉泉[9196] | 15781066479 | 天津市天津市河东区富民路街道月牙河南路与娄山道交叉路口往北约100米金月湾花园7号楼603[9196] |

### 3.2 样本 2（地址在前，逗号分隔，倒序）

```
四川省广安市广安区 中桥街道四川省广安市广安区金安大道三段299号华冠城1701，漆洪兰，13541869970
```

期望输出：

| 收件人 | 手机号 | 收货地址 |
|--------|--------|----------|
| 漆洪兰 | 13541869970 | 四川省广安市广安区 中桥街道四川省广安市广安区金安大道三段299号华冠城1701 |

### 3.3 格式多样性总结

至少存在以下模式：

1. `姓名[编号] + 手机号 + 地址[编号]`（无分隔符）
2. `地址 + 姓名 + 手机号`（中文逗号分隔）
3. 姓名/地址中嵌入 `[数字]` 平台后缀
4. 地址可能存在重复省市区（样本 2）

**结论：** 纯正则无法 100% 覆盖，需「规则引擎 + AI 兜底」双层策略。

## 4. 新增需求：自定义关键词整行标红

### 4.1 功能描述

客户可**自定义关键词列表**（如：驿站、工商局、质检局等）。解析完成后，若某一行**任意字段**（建议默认扫描：收件人、收货地址、备注；不扫描手机号）包含任一关键词，则：

- **界面预览**：该行**整行**填充红色背景（所有可见列统一标红）；可选在标记列显示命中词标签
- **Excel 导出**：该行 **A~I 全列**填充红色背景，实现**整行标红**（不能只标地址列或单个单元格）

### 4.2 典型使用场景

| 关键词 | 业务含义 |
|--------|----------|
| 驿站 | 菜鸟驿站/代收点，可能需特殊配送 |
| 工商局 | 政府机关地址，需人工确认 |
| 质检局 | 政府机关地址，需人工确认 |
| （客户自定义） | 客户自行维护风险词/关注词 |

### 4.3 功能细节建议

| 项 | 建议方案 |
|----|----------|
| 关键词管理 | 支持增删改；默认预置：驿站、工商局、质检局 |
| 匹配方式 | 包含匹配（substring）；可选升级：全词/正则 |
| 匹配范围 | 默认：收件人 + 收货地址 + 备注；手机号一般不匹配 |
| 大小写 | 中文无大小写；若含英文则忽略大小写 |
| 命中多个词 | 显示所有命中词，如红色标签 `驿站` `工商局` |
| 持久化 | 网页版：localStorage；EXE 版：本地 `keywords.json` |
| 导出 Excel | 命中行 A~I 每列均设置 `PatternFill(fgColor="FFCCCC")`，整行标红 |
| 性能 | 批量 500 条内实时匹配，无性能问题 |

### 4.4 界面示意（逻辑）

```
┌─ 关键词设置 ─────────────────────────────┐
│ [驿站] [工商局] [质检局] [+ 添加关键词]   │
└──────────────────────────────────────────┘

┌─ 解析结果预览（命中行整行浅红背景）──────────┐
│ 收件人      │ 手机号       │ 收货地址        │ 标记    │
│▓张三▓      │▓138xxxx▓   │▓某某菜鸟驿站▓   │▓驿站▓  │  ← 整行标红
│ 李四        │ 139xxxx     │ 正常地址        │         │
└──────────────────────────────────────────┘
```

### 4.5 实现要点（Win 开发时）

**Python + openpyxl 导出示例逻辑：**

```python
from openpyxl.styles import PatternFill

RED_FILL = PatternFill(start_color="FFCCCC", end_color="FFCCCC", fill_type="solid")

def row_hits_keywords(row_text: str, keywords: list[str]) -> list[str]:
    return [kw for kw in keywords if kw and kw in row_text]

def apply_row_highlight(ws, row_idx, col_letters="ABCDEFGHI"):
    """命中关键词时，A~I 全列整行标红"""
    for col in col_letters:
        ws[f"{col}{row_idx}"].fill = RED_FILL
```

**前端（若做网页版）**：命中行 `<tr>` 加 class `row-hit`，使**整行**背景 `#ffcccc`；标记列可额外渲染 `<span class="tag-red">驿站</span>`。

## 5. 方案选型回顾

### 5.1 不推荐：给客户装「龙虾 / OpenClaw」

| 维度 | 评估 |
|------|------|
| 解析能力 | 可以，但非开箱即用 |
| Win 客户体验 | 差，需 Node.js、配置、学习成本高 |
| 批量稳定性 | 中低，不适合生产批量 |
| 打包 EXE | 体积大（100MB+），维护成本高 |
| 结论 | 适合内部 prototyping，**不适合作为商户交付方案** |

### 5.2 推荐：分阶段交付

#### 阶段 1（优先）：网页版 MVP

- Mac 可完整开发测试
- 客户 Win 浏览器打开即用，零安装
- 晴红AI Key 放服务端，安全可控
- 关键词红色标签在预览 + 导出两端实现

#### 阶段 2（可选）：Win EXE

- Mac 上**无法本地测试 Win EXE 双击行为**
- 需 GitHub Actions（`windows-latest`）或云 Windows 虚拟机打包
- 推荐做 **WebView 壳**（Tauri/Electron 打开网页）或 **Python PyInstaller 单文件**
- 依赖全部打包进 EXE，客户无需装 Python

### 5.3 Mac 开发 vs Win 交付对照

| 环节 | Mac 能否完成 |
|------|--------------|
| 解析逻辑编写与单元测试 | ✅ |
| 关键词匹配逻辑 | ✅ |
| xlsx 导出格式验证 | ✅ |
| 网页版 UI 全链路测试 | ✅ |
| PyInstaller 打 `.exe` | ❌ 需 Windows 环境 |
| Win 杀软/双击/兼容性测试 | ❌ 需 Windows 环境 |

**务实链路：**

```
Mac 写代码 + 测试逻辑
    → push 到 Git
    → GitHub Actions (windows-latest) 自动打 exe
    → 云 Win / 客户电脑远程验证
```

## 6. 晴红AI 中转站推广策略

### 6.1 架构原则

```
客户端（网页 / EXE）
    ↓ 仅携带：用户 token / 设备 ID（禁止内置 API Key）
晴红AI 中转站（服务端）
    ↓ 鉴权、限流、计费、日志
各大模型 API
```

**禁止：** 将 API Key 硬编码进 EXE（必被反编译提取）。

### 6.2 解析策略（三层）

```
第一层：正则 + 规则引擎（免费，毫秒级，覆盖 80%+ 常见格式）
第二层：字段类型识别（手机号锚点、逗号分隔倒序等）
第三层：调用晴红AI（仅规则失败时触发，JSON 结构化输出）
```

### 6.3 商业化分层建议

| 版本 | 能力 | 目的 |
|------|------|------|
| 免费版 | 纯规则解析 + 关键词标记，每日限额 | 获客 |
| 专业版 | 接入晴红AI 复杂解析，无限条 | 转化 |
| 企业版 | 批量 API + 店铺绑定 + 用量后台 | 续费 |

### 6.4 品牌曝光点

- 页头 / 关于：`Powered by 晴红AI 大模型中转站`
- 复杂样本自动走 AI 时展示「AI 已优化」
- 免费额度用尽引导注册晴红AI
- 导出文件 metadata 或页脚可选水印（低优先级）

## 7. 技术栈建议（Win 落地）

### 方案 A：网页版（一期推荐）

| 层 | 技术 |
|----|------|
| 前端 | HTML + Vue/React 或纯静态 + 轻量 JS |
| 后端 | Python FastAPI / Node Express |
| xlsx | openpyxl（服务端生成）或 SheetJS（前端生成） |
| 关键词 | 前端实时高亮 + 导出时服务端/前端写 fill |
| AI | 后端调晴红AI，客户端无 Key |
| 部署 | 云服务器 / 晴红AI 同域子路径 |

### 方案 B：Python EXE（二期）

| 层 | 技术 |
|----|------|
| GUI | PyQt6 / Tkinter / CustomTkinter |
| 解析 | Python 规则引擎 + requests 调晴红AI |
| xlsx | openpyxl |
| 关键词 | 本地 keywords.json + 表格行背景色 |
| 打包 | PyInstaller `--onefile` on Windows |
| CI | GitHub Actions windows-latest |

### 方案 C：WebView EXE 壳（最省 Win 适配成本）

- Tauri 2.0 或 Electron 加载网页版 URL
- 逻辑全在服务端，EXE 仅壳
- Mac 开发 Tauri 配置，CI 打 Win 包

## 8. 数据流（端到端）

```
用户粘贴原始文字（支持多条，空行分隔）
        ↓
逐条解析 → 收件人 / 手机 / 地址
        ↓
关键词扫描 → 命中则整行标红
        ↓
用户预览、可手动编辑任意单元格
        ↓
导出 xlsx（与千牛模板列一致 + 命中行 A~I 整行红色填充）
        ↓
客户导入千牛批量发货
```

## 9. 风险与待确认项

| 项 | 说明 | 建议 |
|----|------|------|
| `[编号]` 是否写入 D 列 | 目前样本只在 A/C 列 | 问客户 |
| 关键词匹配字段范围 | 仅地址 or 全字段 | 默认全文本字段，可配置 |
| 导出红色是否影响千牛导入 | 一般仅填充色不影响 | Win 上实测导入 |
| 晴红AI 接口格式 | OpenAI 兼容 or 自研 | 开发前对齐 |
| 批量规模 | 单次最多多少条 | 建议支持 500~1000 条 |

## 10. Win 环境执行清单（概要）

详细步骤见同目录 `客户需求梳理.md` 第六节。

1. 准备 Windows 10/11 开发机或云虚拟机
2. 安装 Python 3.11+、Git
3. 克隆/复制项目代码
4. 本地跑通：解析 + 关键词 + xlsx 导出
5. 用 `5.15(3).新表格.xlsx` 对比导出格式
6. 实测千牛导入
7. （可选）PyInstaller 打包 exe
8. （可选）配置 GitHub Actions 自动构建

## 11. 结论

1. **核心能力**：乱序文字 → 标准千牛 xlsx + 自定义关键词命中后**整行标红**  
2. **一期优先网页版**：Mac 可全测，利于推广晴红AI，Key 安全  
3. **二期 Win EXE**：依赖 Windows CI/虚拟机，勿在 Mac 上硬测 exe  
4. **不要用 OpenClaw 直接交付客户**  
5. **关键词功能**实现成本低、业务价值高，应纳入 MVP
